# 1.16 方向：向前生长——让循环从「修补供给器」变成「方向发现器」

> 2026-10-10 两个 Explore subagent 深查产出（供给侧 + 度量反馈侧），证据基于当前工作区 file:line。
> **已过双审查**（证据核查 + 设计对抗审查）：证据 40 处引用全部命中；4 条必须修已并入
> 下文（去重身份 1-1、None/0 配额语义 2-1、升档判据 2-2、近 M 轮口径 3-1），砍/推迟项见文末。

## 问题陈述

三夜自迭代的完成账本：bugfix 131 / test 127 / refactor 39 / docs 37 vs **feature 24 / perf 10**——
新能力约占 9%。三个结构性原因：

1. **供给侧全回望**：mine 的 7 个扫描器有 6 个读文件文本（docs-drift 读的是文档
   而非代码）、1 个读 git 历史；docs-drift 只查「README 引用的文件是否存在」，
   不查「README 宣称的能力是否存在」。16 个视角也全部在检查已有产物。
2. **唯一的向前机制被压制**：种子晋升的 predicted 默认叠加 0.75 冷启动先验 ×
   0.75 缺省 confidence ≈ 0.56 期望折扣（state.py:1291-1307）× risk=2
   （commands.py:1279；手工 `backlog-add --origin predicted` 默认 risk=1，
   commands.py:1757）× 每轮配额 1（config.py:52）× 尾期整切（state.py:1446,1455-1456）
   × 同分排后（state.py:1531）。`compute_predicted_account`（state.py:1171-1208）
   算出的兑现率**只有两个出口**：打分折扣（state.py:1285-1292）和报告展示
   （state.py:2000-2019）——从不反哺配额。
3. **价值判断自我参照且不可见**：type_stats 无 origin 维度（state.py:1046）、
   retro 类型表无 origin 列、check payload 无任何供给配比口径——「只补不长」在
   run 进行中**不可见也不可纠**；外部适应度信号（1.12.x 实测战役）是一次性手工
   战役，仓库内无制度化协议沉淀。

## 机制一：确定性「用户缺口」扫描器（治原因 1）

**目标**：让 feature 类型供给从「agent 判断」升级为「确定性事实」，与 mine 同一条
证据链（`kind | file:line`）。

**设计**：miner.py 新增第 8 扫描器 `scan_user_gap`，1.16 只做两个探针（探针 3
「示例调用不存在的签名」解析误报率高，推迟 1.17）：
- **探针 A 能力差集**：README/SKILL 的能力宣称段 vs 实际公开入口的差集
  （「文档说能 X，代码没有 X」）；
- **探针 B roadmap 段**：TODO/roadmap/「未来计划」类段落 → 显式缺口候选。

**去重身份（审查必须修 1-1）**：user-gap 类发现没有稳定行号（README 一编辑行号
全漂），**身份 = 归一化后的能力宣称文本**（剔行号；标题模板同样不得嵌行号——
`filter_new_findings` 的标题兜底只救逐字稳定标题）。`_dedup_key` 与
`_candidate_dedup_keys` 镜像分支必须是**同一条 key 规则**：后者 if-chain 落错
分支不报错而是每次重复入账（new 虚高 → mine_stale 恒真 → mining_exhausted 永不
触发）。**新增反射性守卫测试**：每个 MINE_KINDS 成员的 `_dedup_key` 产物必须
出现在对应 `_candidate_dedup_keys` 产物集合中。

**职责边界（1-2）**：docs-drift 查「README 引用的 scripts/*.py 文件存在性」，
user-gap 查「能力宣称 vs 入口」——对 docs-drift 已报的缺失路径，user-gap 让位
（同一处缺口不双计供给）。

**分级（1-3）**：`suggested_type` 给 `feature`，但 `effort` 缺省抬到 **3**（文档
差集天然显得价值大，扫描器只供事实、分级留给判断侧；agent 消费前可 backlog-update
重估）。origin 保持 observed（确定性证据非预测），已知代价：机制三的 origin 结算
无法区分「扫描器 feature」与「agent feature」，1.16 接受。

**改动面**：仅 `scripts/autopilot/miner.py` 一个文件——`MINE_KINDS`（86-94）+
`SCANNERS`（545-553）注册（`--kind` choices 自动派生，cli.py:315 零功能改动）；
`_dedup_key`（598-618）与 `_candidate_dedup_keys`（621-662，**必须**补镜像分支）；
标题/文案模板不含行号。**文档四处清单同步 + 一处 help**：config.md:404、
SKILL.md:130、overview.md:13、README.md:29（README 正是 docs-drift 的解析对象，
不同步会变成自家扫描器的靶子）、cli.py:308 的 mine help 字符串（不派生）。

**1.16 不做配套 lens**（判断侧锦上添花，要动 EXPANSION_LENSES + 两张文档表 +
守卫测试三处，推迟）。

## 机制二：预测棘轮——兑现率驱动配额升级（治原因 2）

**目标**：把「猜得准」变成「准许多猜」，形成投机棘轮；猜不准则维持现状。

**单出口**：仿 `effective_saturation_threshold` 先例（state.py:465-476），新增
`effective_predicted_quota(cfg, predicted_account)`。**语义（审查必须修 2-1）**：
- 静态 `max_predicted_per_round` 为 **None（不封顶）→ 恒 None**（棘轮只升不降）；
- 静态为 **0（显式禁）→ 恒 0**（用户禁令优先）；
- 仅静态 ≥1 时参与升档，阶梯判据**模块常量**（不进 config，审查 2-2/2-4）：
  - 档 2：`done >= PREDICTED_SAMPLE_FLOOR(3)` 且 `success_rate >= 0.6` 且
    `calibration >= 1.0`；
  - 档 3：`done >= 8` 且 `success_rate >= 0.7`；
  - 其余（含新 run done=0）：回落静态值。

**接线**：`predicted_account` 在 `rank_candidates`（state.py:1559）已现算，作为
**带默认值的关键字参数**（`predicted_account=None`，None 走现行为）传入
`_mark_selection`（state.py:1410）——生产调用点仅 1 处、测试桩 7 处全部零冲击；
不让 `_mark_selection` 自己重算（entries 是 ranked 副本不是 backlog）。
**升级作用于 `predicted_quota` 变量本身**，主池循环与 below-floor 回填循环
（state.py:1496-1517）读同一变量、自动继承。**late_run 安全阀保持独立**
（1446/1455-1456 正交路径），`cut_reason` 枚举不变。

**开关**：新配置 `predicted_ratchet`（bool，默认 false=现行为），走注册表全配方
（default_config → `_CONFIG_FIELD_RULES` bool 行 → cli init 旗标 + config-set →
config.md/SKILL.md）。注意：**default_config 加键后不注册会直接被
`ConfigFieldRegistryTests.test_registry_covers_every_default_field` 锁红——这是
守卫按设计工作**。

## 机制三：供给配比可见性与告警（治原因 3a）

**目标**：让「只补不长」在 run 进行中可见、可纠——漂移管理化
（与 type_stats_drift 同一哲学）。

**「近 M 轮」口径（审查必须修 3-1）**：类型判定不能事后回查 backlog——
`backlog-update --type` 可翻转已完成候选、`backlog-remove` 可删行，告警可被事后
编辑操纵。修法：**`_close_round` 随 history 条目新增 `candidate_types` 快照**
（_close_round 本就单次持有 backlog，additive 零契约风险）；旧条目回退
`round_candidate_ids`（state.py:445-454，双形态兼容旧标量）+ backlog 现查，
查无此 id 计 unknown 显式排除；**M 只数 `status=="completed"` 条目**；
无候选轮（candidate_ids=[]）计入 M 但不贡献 feature。

**告警规则**：
- 触发：最近 M=8 个 completed 轮的快照类型中 feature=0（completed ≥ 8 才生效）；
- **pending==0 时抑制**（与既有「无 pending → Deep Expansion」告警双响，让位）；
- 文案**同时指向两条补救路**：mine 的 user-gap 扫描器（1.16 后可用）与
  Deep Expansion——因为存量 7 扫描器无一产 feature（审查顺序摩擦），只指 mine
  会是无解告警；
- **不加 action_hint 枚举值**（契约测试锁死四值），只进 warnings 列表——
  纯 additive 零契约风险；`supply_mix` payload 键推迟 1.17（四件套同步成本
  买不来 warnings 之外的信息）。

**retro origin 结算段**：observed/expansion/predicted 三桶完成数，从 backlog
现算（与「复盘恒现算」原则一致，predicted 桶直接复用 compute_predicted_account）。
**窗口口径故意不同并写进文案**：告警 = 滚动 8 轮，结算 = 全 run——候选永不从
backlog 剪除，全量账始终可得。

## 机制四：外部实测波次制度化（治原因 3b）

**目标**：把 1.12.x 战役验证过的外部适应度信号从一次性手工变成常规机制。

**设计**：新顶层 state 数组 `field_test_runs`，schema（审查补丁 A）：
`{at, target_repo, rounds, types_completed, verdict, notes}`——`at` 对齐所有既有
记录的公共字段；`verdict` 枚举 **passed/failed/mixed**（自由文本无法对账）。
**不动 expansion_waves**（三处硬冲突已核实：lens 名校验 commands.py:2857-2866、
`added` 回填只认本仓 predicted/expansion 候选 commands.py:1815-1825（外部实测恒 0
会喂假零产证据给 `mining_exhausted`）、wave cap 语义是本 run subagent 开销唯一闸
check_view.py:627-645）。

**记账而非闸门（审查补丁 B）**：expansion-record 的 cap 存在是因为记录先于
subagent 派遣；field-test 记录是事后记账，**不需要 config cap**，只要列表硬上限
常量 `FIELD_TEST_RUNS_LIMIT = 20`（对齐既有窗口语义）。跨窗 verdict 汇总
（抄 expansion_wave_seq 单调计数器先例）推迟。

**接线**：`default_state`（state.py:44-75）、`migrate_state`（78-132）、
类型校验（197-204，mining_runs/expansion_waves 同款）；helper 新命令
`field-test-record` 仿 `cmd_expansion_record`（2847-2923：锁、log.jsonl 审计、
--json data、verdict 枚举校验）；cli 子命令注册仿 420-434。
`test_state_json_required_keys` 是 assertIn，additive 安全；
`mining_exhausted` 确认只读 mining_runs/expansion_waves，零影响。
