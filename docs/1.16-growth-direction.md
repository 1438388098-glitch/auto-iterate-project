# 1.16 方向：向前生长——让循环从「修补供给器」变成「方向发现器」

> 2026-10-10 两个 Explore subagent 深查产出（供给侧 + 度量反馈侧），证据基于当前工作区 file:line。

## 问题陈述

三夜自迭代的完成账本：bugfix 131 / test 127 / refactor 39 / docs 37 vs **feature 24 / perf 10**——
新能力约占 9%。三个结构性原因：

1. **供给侧全回望**：mine 的 7 个扫描器有 6 个纯读代码文本、1 个读 git 历史；
   docs-drift 只查「README 引用的文件是否存在」，不查「README 宣称的能力是否存在」。
   16 个视角也全部在检查已有产物，没有一个问「用户还缺什么」。
2. **唯一的向前机制被五重压制**：一条 predicted 候选从进池起叠加
   0.75 冷启动先验 × 0.75 缺省 confidence ≈ 0.56 期望折扣（state.py:1291-1307）×
   risk=2 默认（commands.py:1279）× 每轮配额 1（config.py:52）×
   尾期整切（state.py:1446,1455-1456）× 同分排后（state.py:1531）。
   且 `compute_predicted_account`（state.py:1171-1208）算出的兑现率**只有两个出口**：
   打分折扣（state.py:1285-1292）和报告展示（state.py:2000-2019）——从不反哺配额。
   兑现率再高配额恒为 1，再低也只压分数。
3. **价值判断自我参照且不可见**：type_stats 无 origin 维度（state.py:1046 只做了
   排除 predicted）、retro 类型表无 origin 列、check payload 无任何供给配比口径——
   「只补不长」在 run 进行中**不可见也不可纠**；外部适应度信号（1.12.x 实测战役）
   是一次性手工战役，仓库内零沉淀（无 skill-lab、无 PROTOCOL.md）。

## 机制一：确定性「用户缺口」扫描器（治原因 1）

**目标**：让 feature 类型供给从「agent 判断」升级为「确定性事实」，与 mine 同一条
证据链（`kind | file:line`）。

**设计**：miner.py 新增第 8 扫描器 `scan_user_gap`，探针面：
- README/SKILL 的能力宣称段 vs 实际公开入口的差集（「文档说能 X，代码没有 X」）；
- TODO/roadmap/「未来计划」类段落 → 显式缺口候选；
- 公开 API 面与文档示例的差集（示例调用了不存在的签名）。

**改动面（最小）**：仅 `scripts/autopilot/miner.py` 一个文件——
`MINE_KINDS`（86-94）+ `SCANNERS`（545-553）两处注册（cli 的 `--kind` choices
自动派生，cli.py:315 零改动）；`_dedup_key`（598-618）与
`_candidate_dedup_keys`（621-662，**必须**补镜像解析分支，否则去重失效重复入账）；
`suggested_type` 给 `feature`。文档三处清单同步：config.md:404、SKILL.md:130、
overview.md:13。

**配套 lens**：可同时注册 `user-gap` lens（state.py:571-588 +
expansion-lenses.md 两张表，守卫测试 `test_lens_catalog_matches_constant`
自动校验同序同名）——扫描器供事实、lens 供判断，两条腿。

## 机制二：预测棘轮——兑现率驱动配额升级（治原因 2）

**目标**：把「猜得准」变成「准许多猜」，形成投机棘轮；猜不准则维持现状。

**设计**：仿 `effective_saturation_threshold` 单出口先例（state.py:465-476），
新增 `effective_predicted_quota(cfg, predicted_account)`：
- 样本 < 3（`PREDICTED_SAMPLE_FLOOR`）：回落静态 `max_predicted_per_round`（默认 1）；
- done ≥ 3 且 success_rate / calibration 达标（阈值可配，默认如 success_rate ≥ 0.6
  且 calibration ≥ 1.0）：升档 1 → 2 → 3（封顶可配或 null=不封顶）；
- 兑现率差：维持 1，不额外惩罚（打分层已有折扣，不重复罚）。

**接线**：`predicted_account` 在 `rank_candidates`（state.py:1559）已现算，
作为参数传入 `_mark_selection`（state.py:1410），不改其签名语义、不在函数内重算。
**late_run 安全阀保持独立**，不受升级影响——尾期保守是另一条正交原则。

**风险与约束**：`_mark_selection` 行为被大量既有测试锚定
（test:838-903 / 1048-1064 / 2529-2546）——**升级默认关闭（=现行为）**，
用新配置开关（走 config 注册表全配方：default_config → _CONFIG_FIELD_RULES 行 →
cli 旗标 → config.md/SKILL.md，`ConfigFieldRegistryTests` 自动守卫漏注册）
打开后才生效；`cut_reason` 枚举不变，配额升级路径照旧标注 `quota`。

## 机制三：供给配比可见性与告警（治原因 3a）

**目标**：让「只补不长」在 run 进行中可见、可纠——漂移管理化
（与 type_stats_drift 同一哲学）。

**设计**：
- check 新增双语 warning（照 calibration-inactive 先例，check_view.py:266-276，
  纯 additive 零契约风险）：触发条件如「completed ≥ N 轮且近 M 轮完成中
  feature=0」或「pending 里 feature 占比 < 配置下限」；
- retro 类型表增 origin 结算段（observed/expansion/predicted 三行完成数），
  让 9% 这种事实每夜可对账；
- 可选 payload 键 `supply_mix`：须四件套同步（契约测试键集 test:4651-4664、
  backlog/expansion 对象键集、config.md:394 键清单、TypeStatsDrift 同款测试）。

## 机制四：外部实测波次制度化（治原因 3b）

**目标**：把 1.12.x 战役验证过的外部适应度信号从一次性手工变成常规机制。

**设计**：新顶层 state 数组 `field_test_runs`（target_repo / rounds /
types_completed / verdict / duration），**不动 expansion_waves**——subagent 调查
确认后者三处硬冲突（lens 名校验 commands.py:2857-2866、`added` 回填只认本仓
predicted/expansion 候选 commands.py:1815-1825（外部实测恒 0，会喂假零产证据给
`mining_exhausted` 的波次项）、wave cap 语义是本 run subagent 开销唯一闸
check_view.py:627-645）。同步 `default_state`（state.py:44-75）、
`migrate_state`（78-132）、类型校验（197-204）；helper 新命令仿
`cmd_expansion_record`（2847-2923：锁、log.jsonl 审计、--json data）。
`test_state_json_required_keys` 是 assertIn，additive 安全。

## 实施顺序（按性价比）

1. **供给配比告警 + retro origin 段**（机制三）——最便宜，立刻让漂移可见；
2. **user-gap 扫描器 + lens**（机制一）——单文件为主，直接补 feature 供给；
3. **预测棘轮**（机制二）——有 effective_saturation_threshold 成熟先例，
   默认关闭风险可控；
4. **实测波次记账**（机制四）——唯一动 state schema 的，放最后。
